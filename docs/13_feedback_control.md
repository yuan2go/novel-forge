# 13. 评论反馈控制系统 Feedback Control

## 1. 模块目标

评论反馈控制系统负责让读者最新评论影响小说发展，但不让小说失控。

核心原则：

```text
评论可以影响局部节奏。
评论不能突破项目宪法。
评论可以修正读者体验。
评论不能替代主线判断。
```

## 2. 评论影响范围

评论可以影响：

```text
后续 3-10 章节奏
某个配角戏份
某个爽点频率
某个伏笔回收时机
解释密度
压迫与反击节奏
局部情绪补偿
```

评论不能直接影响：

```text
项目宪法
世界宪法
哲学终局
主角核心欲望
反派核心逻辑
最终结局
共享世界核心设定
原创风险边界
```

## 3. 每日反馈流程

```text
收集评论
  ↓
DeepSeek 分类
  ↓
Claude Code 生成 feedback_analysis.md
  ↓
ChatGPT/Codex 判断可采纳性
  ↓
写入 feedback_decision.md
  ↓
更新后续 3-10 章细纲
  ↓
更新 decision_log.md
```

## 4. 评论分类

| 类型 | 含义 | 处理方式 |
|---|---|---|
| 爽点命中 | 读者喜欢某个反杀、升级、揭密 | 可强化 |
| 节奏问题 | 读者觉得拖、水、解释多 | 优先调整 |
| 人物喜欢 | 读者喜欢某角色 | 可增加功能性戏份 |
| 人物反感 | 读者讨厌某角色 | 判断是有效厌恶还是失败塑造 |
| 设定疑问 | 读者不理解世界规则 | 用剧情补说明 |
| 追读期待 | 读者想知道某伏笔 | 可提前部分回收 |
| 弃读风险 | 大量读者表达无聊、看不懂、不爽 | 必须处理 |
| 错误建议 | 读者建议违背主线或项目宪法 | 不采纳 |
| 情绪争议 | 评论两极分化 | 观察，不立即修改 |

## 5. 反馈分级

### S 级反馈

标准：

```text
大量读者集中反馈；
影响追读；
涉及节奏、看不懂、不爽、主角憋屈过久。
```

处理：

```text
立即调整后续 1-3 章。
```

### A 级反馈

标准：

```text
部分读者高频提及；
不影响主线；
可以增强阅读体验。
```

处理：

```text
调整后续 3-5 章。
```

### B 级反馈

标准：

```text
少量评论；
方向不明确；
可能只是个别偏好。
```

处理：

```text
记录，不立即调整。
```

### C 级反馈

标准：

```text
违背项目宪法；
违背主角成长线；
破坏哲学方向；
让小说变成读者点菜；
会导致后续失控。
```

处理：

```text
记录为 not_adopted，并说明原因。
```

## 7. 防失控红线

### 红线 1：不改项目宪法

评论不能直接修改：

```text
目标读者
核心卖点
主角核心欲望
哲学终局
世界第一规则
反派核心逻辑
```

### 红线 2：不让配角抢走主角线

读者喜欢配角可以加戏，但不能：

```text
替主角完成核心成长；
抢主角关键选择；
替主角解决主线冲突；
让主角变成旁观者。
```

### 红线 3：不因单日评论大改大纲

重大调整需要：

```text
连续 3 天趋势；
评论数量支撑；
与追读或弃读相关；
不违背项目宪法；
主编确认。
```

### 红线 4：反馈只默认影响 3-10 章

日常反馈不直接改长期终局。

## 8. 反馈进入全局知识库条件

只有满足以下条件，项目反馈才能升级为全局规律：

```text
多个项目都出现类似反馈；
连续多天稳定出现；
与追读或弃读相关；
不是个别读者偏好；
不违背商业常识；
不破坏小说基本结构。
```

示例：

```text
多个项目中，读者都抱怨主角连续受压太久。
```

升级为全局规则：

```text
主角连续受压不得超过 3 章，除非第 4 章给予信息胜利、行动胜利或情绪补偿。
```

## 10. 验收标准

一次反馈处理必须：

1. 完成评论分类；
2. 完成反馈分级；
3. 明确是否采纳；
4. 明确影响章节；
5. 不破坏项目宪法；
6. 写入 feedback_decision.md；
7. 写入 decision_log.md；
8. 必要时更新后续 3-10 章细纲。

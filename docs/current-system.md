# Current system

## What Novel Forge is today

Novel Forge is a local-first, PostgreSQL-authoritative AI novel production runtime. It
combines versioned story-design and planning Authorities with durable book/chapter
coordination, governed Provider and object-store effects, candidate review gates, and an
atomic transition from a qualified chapter candidate to accepted narrative facts.

It is not a one-shot prompt generator, a complete autonomous Agent product, or proof of
long-form production quality. The current machine projection is
`architecture/reality-evidence.json`; executable code, schema, migrations, composition
and current tests remain its source, never the reverse.

Capability states are ordered `CODE_EXISTS`, `WIRED`, `EXECUTABLE`, `QUALIFIED`, and
`PRODUCTION_PROVEN`. A lower state never implies a higher one. The projection binds its
implementation-tree identity, and Documentation Reality fails when code or instruction
identity changes without a corresponding projection update.

`CONDITIONAL`, `REJECTED`, `UNKNOWN`). Typed prerequisites, exceptions and hard conflicts
use deterministic predicates against the frozen input versions; textual judgments retain
uncertainty. These checks establish applicability to supplied inputs, not real-world truth.
Planning, Formation and World Preparation must explicitly adopt, adapt or reject each
selected Card. Adoption identifies a concrete candidate field, literal realization,

reselect rejected project knowledge. Scoped inherited mechanisms survive repetition

mechanism conditions and exceptions. Missing promised mechanisms and unresolved hard

The narrative qualification report follows abstraction and dependencies, not chapter-count
stages. Each layer retains its own observed proof and upstream blocking status. A missing
upper contract blocks downstream qualification even when candidate prose exists. The
report reads native immutable evidence; it does not activate plans or accept prose.

## Bounded long-form retrieval

Retrieval binds one campaign to the exact project, book, accepted-through chapter,

Production Execution may return a typed query-expansion proposal through the existing

cannot name admissible AssetVersions or expand the accepted boundary. Context Authority

path. Source isolation, actor knowledge, accepted boundaries, final Context admission

## Narrative Reality and causal production

`NarrativeRealityRevision` references the exact Book acceptance, ChapterOutcome,
Narrative State, Canon and long-form projection set. Its immutable identity includes
its parent revision and source digest. PostgreSQL requires one revision for each
contiguous accepted frontier. Book acceptance inserts the revision and its derived
event index in the same transaction as cursor advancement. Neither an unaccepted
Draft nor a successful but unaccepted ChapterOutcome can advance this chain. Rebuild
starts from the original frozen Book input and replays accepted outcomes.

World Foundation extends the existing Story Design World asset with core ontology,
genre and Book-owned sections. Sections declare compilation scope and depth; they
need not describe every category before production begins. World rules distinguish
deterministic hard, quantitative and temporal predicates from soft causal suggestions.
Candidate transitions declare on-camera, off-camera or undercurrent effects, exact
story time, actor, changes and accepted causes. Known Character actions require their
own accepted knowledge or belief predicates. The world
clock advances from accepted world transitions, independently of narrative flashforwards.

Native Book supervision requests world preparation before Chapter planning. The
Planning operation freezes the approved Foundation set, current Intent, Book input
snapshot, accepted frontier, world rules, approved Character definitions, active Planning
window, ControlPolicy and bounded production policy.
Before the first acceptance, the baseline is a content-bound Foundation projection;
there is no synthetic chapter-zero acceptance. Subsequent rounds bind the exact
Narrative Reality revision.

`world_candidates.generate` and `world_candidates.evaluate` use the existing Planning
Capability Pack, Context admission, Provider Effect, receipt and budget boundaries.
The first stage supplies proposed transitions and preparation alternatives; the second
supplies Director dimensions and reasons. Deterministic rules reject unsupported
identities, causes, epistemic bases, quantities and times before selection. Candidate,
path, step, chapter-window, world-time and Context limits are frozen policy. A reasoned
`NO_OP` or `DEFER` is a valid result. Exhausted legal alternatives produce `BLOCKED`.
Model explanations remain hypotheses; formal checks cover the modeled predicates only.
The explicit `planning.causal.propose` API remains a manual proposal input.

Only the selected preparation path creates commitments. Its steps bind dependencies,
future Chapter windows and expected effects. Private preparation uses the Narrative
State reducers but has no accepted authority. A target may cite its own declared preparation
events: the complete path graph is validated before target eligibility, with exact historical
references and path-local scope. Provider array order does not determine dependency order.
Native planning resolves accepted preparation commitments before generating a fresh
portfolio. Due steps retain their original action/path identity; accepted event mappings
prevent duplicate execution, and fresh `NO_OP`/`DEFER` cannot discard them. Continuation
records execution, waiting, deferral, blocking and cancellation decisions against the new
frontier. An exact accepted effect from another event can support an unexecuted step,
with a separate reuse receipt rather than a fabricated execution record.
Planning completion cannot discharge a
commitment: repayment requires an exact accepted predicate event. Approved replacement
Intent can retire unfulfilled preparation while preserving its original decision and
accepted history. An expired unfulfilled window produces an accepted cancellation;
renewal creates a new commitment linked to that retirement event. Target retirement is
separate from predicate repayment: an already fulfilled preparation retains its payoff
receipt when the target expires or is cancelled, and its terminal target is no longer scheduled.
Selected on-camera events are assigned to one Scene and carried in a frozen public execution
contract. Observer must find the exact effects and local dependency identity in the final
prose before Book acceptance records the original action/step mapping. Its observed causal
transition must match the scheduled actor, time, effects and modeled prerequisites; the
observed action description is preserved. Missing or different observation cannot be
filled from the plan. Observer-only validation constraints remain outside Writer and
Quality text views, including the metadata of already accepted visible events. Missing execution
leaves the step pending; a successful chapter alone cannot complete it.

Selected background events enter Canon reconciliation with a governed source origin
that binds the source, generation, evaluation, selected transition and acceptance
policy. They carry no fabricated prose span. Book acceptance checks that the complete
background payload still equals that decision, then commits background and observed
facts in the same acceptance transaction and Reality lineage. Major changes retain
Canon and ControlPolicy approval gates. Rejecting the chapter leaves no background
fact. An accepted event cannot be withdrawn by a later Director choice.

World and Director Context can inspect their governed source projection. Writer and
Chapter Context exclude private world bindings and undisclosed background facts,
including previous-outcome and retrieval summaries. A planned disclosure references
an existing accepted event; only its accepted presentation changes the selected
character or reader audience. It does not create the objective event again. Disclosure
resolves exact historical occurrences through the accepted event index, even after the
entity's current state advances. Historical occurrence and current assertion are distinct:
a superseded state cannot be presented as a current assertion. Versioned audience policy
selects scalar fields and an explicit mode; mixed audiences use separate records.
Character-only disclosure does not expose hidden content to Reader-facing production.
Misdirection and withholding cannot grant new objective Character Knowledge, even when
Observer proposes a KNOWN record alongside that presentation.
Partial presentation cannot expand into the full fact through Context or retrieval.
Scene epistemic projections retain explicit Scene and Character scopes. Hidden
preparation commitments remain outside the Reader view.

Explicit batch-local event names and dependencies order same-chapter acceptance.
Each event validates against the frozen baseline plus its verified ancestors through
the same reducers. Cycles, unknown references, future causes, unordered writes and
cross-character knowledge fail before the atomic commit. Compiled rules are also checked
against the combined final projection, including effects outside each event's ancestor set.
Local names resolve to exact
accepted event identities in Why traces. Independent simultaneous events remain legal;
travel uses the affected entity's clock. Retry reuses frozen Context and confirmed
Provider outputs, and ChapterGroup recovery consumes a committed Book acceptance

## Persistence, effects and recovery

PostgreSQL owns production business and execution facts. `AuthorityUnitOfWork` rolls back
unless explicitly committed, and composed owner mutations use the declared transaction
or savepoint boundary. The migration registry and migration manifest jointly determine
the current head; canonical prose intentionally does not duplicate its identity.

Provider and MinIO-compatible object-store calls use durable ExternalEffect intent,
dispatch generation and receipt records. A request that may have started is reconciled
before retry and is never blindly resent. Idempotency keys bind the request digest;
Attempt leases and fencing reject stale workers. Safe database retries are restricted to
classified SQL states, while an unknown commit result requires evidence-based
reconciliation. Recovery appends attempt, receipt, checkpoint or replacement lineage and
does not rewrite terminal history.

Book acceptance is the decisive narrative mutation: one transaction advances the cursor
and binds ChapterOutcome, accepted Canon/Narrative State inputs, long-form projections,
the Narrative Reality revision, audit and outbox evidence. Reader and recap work follows asynchronously and remains
advisory.

## Semantic constraint classes

Only `CURRENT_PROVEN_INVARIANT` statements may be treated as canonical architecture
invariants. Current implementation shape is `CURRENT_RUNTIME_FACT`; thresholds and
limits owned by profiles or frozen capability packs are `CONFIGURABLE_POLICY`; import
adapters for retired shapes are `HISTORICAL_COMPATIBILITY`; and undecided domain meaning
is `UNRESOLVED_DESIGN_CONSTRAINT` with `design_review_required=true`.

The current proven set includes atomic Book chapter acceptance, no blind resend after an
ambiguous external effect, candidate/accepted-actual separation, raw-source isolation,
and Arc identity independent of Volume containment. The typed planning levels, planning
horizons, five Book Opening layers and the minimum evaluator behavior are current runtime
facts, not claims of final design. Quality thresholds, retry counts and context budgets
are configurable policies. The pre-hierarchy import flag is compatibility-only.

ChapterGroup now requires only positive ordered bounds at the domain boundary. Maximum
and preferred execution lengths belong to immutable, project-selected policy frozen per
Book run. ReaderProxy score bands and issue thresholds likewise belong to their own
versioned policy, frozen at admission and replayed unchanged after project policy edits.
Both configuration paths use governed commands, PostgreSQL integrity, trace, audit and
outbox evidence. Their numeric defaults are not universal narrative invariants.

A single-chapter execution window still requires every chapter-function row constraint.
Its reader-experience homogeneity comparison reports `NOT_APPLICABLE` with one
observation; this does not establish diversity or narrative quality. Comparisons across
multiple rows retain their blocking homogeneity checks.

Independent relationship/thematic trajectory portfolio activation remains unimplemented;
current character/Arc contracts and accepted relationship projections do not establish
that capability. It requires explicit design review rather than promotion of generic
plan fields into a second Authority.

## Corpus ingestion and governed knowledge bridge

Source Authority owns the Corpus catalog, immutable rights/snapshots, content bindings,
and imports. MKAOS owns abstraction review, decisions, Cards and Packs; Context and
Provider still enforce actual consumption. No parser or downloader acquires fact-write or
knowledge-approval authority.

| Existing mechanism | Content ingestion extension | Owning production entry |
| --- | --- | --- |
| `source.corpus.commit` and immutable Edition/admission | exact acquisition and per-work rights scopes | Source Authority |
| SourceImportJob, Command Kernel Attempt/Lease/Fence | `corpus_content` jobs and acquire/work operations | Source Import worker; `novel-forge corpus` |
| Git acquisition and ExternalEffect receipts | fixed GitHub commit/path, bounded local/HF/IA adapters | `CorpusAcquisitionAdapter` |
| SourceDocument/Transform/SourceWork/Unit/Chunk | streamed format records and exact Edition bridge | `CorpusIngestionRuntime.process_work` |
| Source analysis and MKAOS decisions/Packs | current authorization and physical-source checks | existing Source/MKAOS applications |
| Planning Cards and governed Provider input | shared lineage admission at new consumption | MKAOS query and execution payload resolver |

`source.import.corpus.acquire` freezes the requested/resolved manifest and analysis policy
at admission. It obtains verified bytes through `source.remote.fetch`, stores verified
Blobs through object-store Effects, freezes a snapshot and admits bounded Edition batches.
`source.import.corpus.work` maps one bounded work into the existing Source content model.
The bridge binds project, Edition, exact parsed bytes/parser hash, SourceDocument,
Transform, SourceWork, normalized hash, rights, policy and Operation. PostgreSQL guards
reject mismatched scope, acquisition receipts, blobs or immutable bindings. A metadata-only
Corpus declaration is still not evidence of downloaded bytes.

Local acquisition detects inode/size/time changes during reading. GitHub fixes a full
commit and explicit files; its existing Git adapter limits each selected blob to 8 MB and
rejects LFS pointers, submodules and symlinks. Hugging Face fixes commit/files and verifies
explicit config/split mappings when requested; it executes no dataset code. Internet
Archive compares item/file metadata before and after acquisition, checks published MD5/SHA1
when present and computes its own SHA-256. Item names and access times are not immutable
content identities. Remote transport rejects private addresses, unapproved redirect hosts
and credential URLs. Access-denied responses never trigger authentication bypass.

TXT uses an explicit strict encoding (including GB18030/GBK/Big5); EPUB follows the spine;
HTML uses configured body/noise selectors. JSON, JSONL and Parquet map explicit work,
Edition and chapter keys, with a bounded disk index joining chapters across shards.
ZIP/TAR expansion rejects unsafe paths, links, special files and excess expansion.
Per-file/work/record, total byte, memory, disk, timeout, retry and concurrency limits are
frozen. Versioned Chinese TXT segmentation reads strict decoded lines under a body-unit limit; ambiguous or missing
structure is `REVIEW_REQUIRED`; excerpts remain excerpts. Unicode positions, normalized
UTF-8 offsets and raw record/member locators are distinct. Unknown original offsets remain
null. Chinese heading/volume and explicit byte-boundary profiles preserve original locators.
A disk index compiles bounded works; the existing SourceWork materializer still assembles
a work within the frozen per-work/memory allowance. Embeddings and classification remain
separate capabilities; a matching content hash never transfers rights.

Rights distinguish dataset license from underlying prose. `SELECTED_WORKS` declarations
add exact work-key grants; root restrictions and purpose denials still apply. Corpus purpose
and the explicit uses `LOCAL_PROCESSING`, `SOURCE_ANALYSIS`, `ABSTRACT_GENERATION` are
independent gates. Missing use grants deny use. Unknown/conflicting/restricted underlying
rights cannot authorize production-reference. Research cannot become production knowledge;
Benchmark cannot enter the Source generation/analysis bridge. Production membership alone
does not authorize model calls or abstract generation. Source analysis additionally needs
its existing governed runtime, approved policy and bounded Provider budget.

Restricted research freezes a Source Observation Boundary instead of a production
accepted cursor. An acknowledged numbering discontinuity can permit reading its exact
available chapter unit only when the issue locator and normalized hash match that unit.
The issue remains blocking for whole-work completeness, and `REVIEW_REQUIRED` is not
upgraded. Unacknowledged, unlocalized, mismatched or other intersecting integrity issues
still reject consumption. The registered boundary reaches the same Provider recheck;
this exception does not grant Writer or public use.

Reference compression retains recognized chapter headings as required source units.
Multiple groups share one candidate target instead of receiving that target each time;
nonpositive group allocations and an aggregate mandatory-unit floor above the target
stop before a semantic call. Fidelity restoration and the
final aggregate budget still apply. These deterministic protections do not establish
semantic fidelity or a net cost benefit for lossy compression.

Known Corpus bytes and exact Git acquisition paths cannot be relabeled through legacy
Source registration or a SourceWork wrapper to omit lineage. Unbound legacy sources keep
their existing governance. New approvals, Packs, planning references and Provider input
resolve bounded provenance and current rights. Retirement, new rights or a later Corpus
binding deny affected new consumption; historical results stay replayable. Authorization
checks share the Source project's PostgreSQL advisory lock with rights/binding mutations.
Raw SourceDocument/Transform/Chunk/SourceWork remain prohibited generation inputs, even
when their Corpus rights permit abstract knowledge use. Only governed knowledge can cross
that boundary. Fixture-derived Cards retain their fixture ceiling and cannot pass a
production Planning gate merely because a Pack can be inspected.

Import results distinguish preview, verified acquisition, parsed content, scheduled
analysis and knowledge approval. Pause stops new stages; the current stage may finish.
Cancellation uses the Kernel and does not remove accepted content. Committed stage results
replay without another acquisition; a restarted worker reconciles a known receipt before
continuing. Unknown Effects are not blindly resent. Only known HTTP 502/503/504 responses
allow bounded full re-fetch within the frozen retry limit; range continuation is not
claimed. Terminal failures require a new run key and preserve old failure/byte evidence.
New requests resolve the current snapshot/rights at admission; the same run key reuses its
original frozen identities. See [runtime operations](runtime-operations.md#corpus-content-ingestion)
for the native entry and bounded examples.

Acquisition receipt v2 separates immutable byte identity from the idempotent operation
receipt; independent imports of identical bytes cannot reuse a timestamp-bearing receipt.
Frozen v1 receipt queries retain their original identity. Source Authority scopes all
Corpus command keys by project/workspace; only an existing exact-scope legacy key is reused.

Corpus processing revisions append to the acquired Edition without a new acquisition.
`source.import.corpus.work` also executes reprocessing admitted through the existing
SourceImport application surface. SourceWork publication, exact Bridge, assessment,
fingerprint, descendant invalidation and stage result share one UoW. Other materialized
SourceDocument/Transform candidates are unusable until their exact document Bridge exists.
The bridge binds the consumed SourceWork version; new consumption rejects superseded
processing. Historical outputs remain queryable. Frozen parser-v1 output preserves its
structure-contract ceiling; it is not backfilled as a verified full-book assessment.

Parser v2 stores one frozen profile per parsed work; units reference its digest, avoiding
repeating a full ToC for every chapter.

`corpus-parser.v2` and v3 separate source completion, selected-edition coverage, verified bytes
and structural usability. Counts/continuous numbering alone never establish completeness.
A supplied exact ToC is checked against actual titles; unverified coverage stays UNKNOWN.
Findings retain raw locators and hashes. Source Corpus commands append scoped review
and pairwise equivalence decisions. Non-body exclusions require reprocessing; the raw
units remain in the immutable source bundle. A changed parser cannot silently erase an
unresolved prior issue. Explicit boundary overrides require checksum-bound, complete,
non-overlapping raw byte coverage. They can close only matching boundary findings; unrelated
issues remain open. Processing inspection also returns bounded downstream invalidation evidence.

Exact text/structure/unit hashes and a versioned bottom-k shingle signature support
bounded indexed candidate discovery and version comparison. Traditional-to-simplified
conversion and punctuation/space removal apply only to the matching projection.
Equivalence requires an explicit decision; pair decisions never imply a transitive merge,
change source rights, or authorize knowledge reuse. Revoke appends to the same pair's
history. Candidate discovery is bounded and may be incomplete; scores are estimates,
not probabilities or proof of literary/work identity.

Parser v3 freezes `chinese-longform.v2`. Its unit identity includes the stable file/member,
record/spine and local span; earlier frozen v1/v2 tasks retain their contracts. Confirmed
headings alone are excluded from exact body hashes. Repeated bodies become grouped findings
under a versioned minimum-length policy; short repeated formulae remain notices. No unit is
automatically deleted. Number/title conflicts are scoped to volumes. Catalogue comparison
normalizes number notation, whitespace and punctuation only; raw titles and acquisition
locators remain unchanged. Entry-level decisions distinguish confirmed display/wording
variants from annotations that keep an issue blocked. A new catalogue cannot inherit a
prior title waiver. Reprocessing re-evaluates conflicts caused by exact reviewed exclusions
and records which decision resolved each finding. Annotation-only revisions also receive
an exact SourceWork/Bridge binding, even when prose and parser hashes are unchanged.

`resolve_canonical_works` appends explicit work/member revisions; one Source transaction can
split, move, merge or retire up to eight groups. Negative pair decisions prevent grouping.
Typed `declare_relation` evidence distinguishes same work, same Edition/copy, revision,
abridgement, expansion, excerpt, similarity, difference and uncertainty. Directional evidence
retains subject/reference identities. Old untyped ACCEPT decisions keep their original
pair-only meaning. Neither grouping nor cached similarity transfers source permissions.

Comparison retains occurrences, volume and order, aligns exact units/bodies before bounded
similarity candidates, and pages correspondence with an input/review-bound cursor.
Discovery enumerates exact hashes first, then indexed fingerprint/metadata candidates, with
stable pagination and an explicit incomplete-recall ceiling. New processing invalidates an
old discovery cursor; historical targets require explicit selection.

`revise_curated_corpus` creates an inspected candidate manifest and freezes an explicitly
selected subset (at most 100 members). Edition, Processing, canonical revision, review,
rights and purpose membership remain exact; omitted/blocked candidates remain visible.
Current Source admission, Processing/Review and canonical membership are checked at freeze,
analysis admission, worker dispatch and Provider send. Curated analysis reuses
`source.import.corpus.analysis` coordination and the existing profiling/deconstruction/MKAOS
children. Call/token ceilings use the existing project ledger conservatively; concurrent
project usage consumes the same ceiling. No knowledge is automatically approved. Pause,
cancel, fence recovery and terminal result replay remain SourceImport/Kernel operations.
Raw SourceWork/Corpus bodies still cannot enter Writer context.

Curated job queries resolve the exact frozen Operation, revision, members, purpose and
budget. They never infer a snapshot for a multi-source selection. Member/stage results,
formal output references, candidate/Card/Pack counts and known/unknown ledger records are
read-only projections; coordinator success is distinct from completed analysis. The CLI
runs job-scoped eligible work with existing lease/fence recovery and reports partial,
paused, cancelled, stage-bound and leased outcomes separately. New and legacy pair
commands share canonical-group conflict validation; a deferred PostgreSQL constraint
checks the final membership state. A changed relation evidence set requires a new inspected
curated revision for new execution; frozen results remain queryable. Source profile,
Observation and MKAOS candidate publication recheck the originating curated selection
inside the owning transaction under the Source authorization lock. Confirmed Provider
receipts remain evidence when a changed selection blocks publication.

`corpus-parser.v4` adds EPUB logical chapters over ordered physical spine fragments.
TOC/NCX/nav anchors define reading intervals; verified headings can split a spine item.
A title-only final segment can receive its body from the next linear resource. Other
unheaded cross-resource continuation requires an exact acquisition-bound declaration.
Unknown prefixes remain review findings. Logical fragments retain member hashes, extracted
Unicode ranges, normalized Unicode/UTF-8 ranges and the LF joining rule. Image-only
unclassified body resources, missing anchors and conflicting TOC order fail closed.
Declared cover images and semantic non-body resources retain explicit provenance.
Versions v1–v3 retain their frozen parser serialization and behavior. Reprocessing v4
reuses the acquired bytes and Edition and appends a Processing/Bridge; an old finding is
replaced or resolved only when its exact evidence maps to a new occurrence or supported
logical body. Format agreement for one acquired Gutenberg item is not independent edition
or worldwide-rights proof.


## Qualification ceiling

`make p0-backend-qualification` is the single high-level backend engineering gate. It
binds a clean implementation revision, complete non-PostgreSQL and PostgreSQL test
collections, fresh and supported-upgrade migrations, query plans, scripted Compose
runtime/recovery and zero-residue cleanup. A capability can be `QUALIFIED` only while a
retained passing report matches the current implementation-tree identity and covers its
test references.

P0 uses scripted Provider behavior. It establishes local backend, PostgreSQL and recovery
engineering only. Credentialed Provider execution is separately qualified and becomes
stale when implementation or instruction identity changes. Neither route establishes
admin UI execution, human editorial evidence, longitudinal narrative stability or
production operation. No current capability is `PRODUCTION_PROVEN`.

### Bounded Chinese creation pilot

The native creation runner prepares isolated Project/Book records through existing
Commands, freezes the pilot policy in Book runtime policy, and locates Formation and
Opening by their original idempotency keys on resume. Confirmed outputs remain owned
by the existing runtime. A project lifetime Provider cap spans Formation, Opening,
chapters, revisions and retries; an explicit total authorization is required for paid
execution. Configuration checks do not call a model.

The Chinese pilot policy requires 2000–3500 Han ideographs per chapter under
`HAN_CHARACTERS_V1`, independently of model scores. It is separate from the small
English engineering smoke. The workspace and exports resolve committed Acceptance
through its immutable ChapterOutcome, then verify exact Candidate/Quality/Review/Canon/
Context/Memo bindings and hashes. Historical Quality targets remain in the workspace.
Partial exports retain completed files and explicit errors. These contracts establish
engineering behavior; real creative effects require actual authorized text and receipts.

Bounded narrative reading extends curated `reading_scopes`. Each selected member freezes
exact Edition/Processing, ordered SourceUnit versions, permitted adjacent context, chunk
hashes, review/rights/member references, dimensions and byte/repair bounds. `CHAPTER_WINDOW`
profiling independently validates that frozen manifest in Source Authority; `FILE_DOCUMENT`
retains its complete-transform requirement. Model route, prompt/schema, Skill digests and
runtime budget configuration are frozen before dispatch. Changed configuration blocks new
calls; known Effects remain replayable. Preview does not grant model authorization.

SourceImport schedules chapter observation, semantic review and bounded directed repair,
then ordered synthesis over accepted lower observations and existing MKAOS extraction.
The existing AnalysisPlan, Deconstruction Operation, Provider Effect and budget ledger own
execution. Only a failed chapter/synthesis is revised; original candidates, unresolved
issues and receipts remain immutable. Exhausted repair budgets block. Mechanical extraction
failure is distinct from a valid finding-free result, which creates no invented knowledge.

Observations distinguish explicit text, supported inference, hypothesis and unknown, with
narrator/character/reader/analyst perspectives, entity and causal references, and structured
prerequisite, choice, cost, consequence and information details. Exact chunk UTF-8 spans
must match the quoted text. Synthesis sees ordered verified observations, not unsent chapters
or remembered whole-book outcomes. Its precise evidence spans are resolved through bounded
lower-observation lineage before MKAOS extraction. Agent review is not independent semantic
or human proof; Candidate, approved Card, Pack and generation eligibility remain distinct.
Research/Benchmark/Fixture, revocation and stale-version consumption guards still apply.

Reading results separate actual text, lower observations, permitted unread context and
unknown outside scope. Coverage records supplied input, not understanding. An authorized
query exposes at most 4096 UTF-8 bytes of an actual stage input; it checks current admission
before and after object reading. Metadata/receipts remain queryable after consumption is
revoked. Querying never creates model calls or resets a budget.

`corpus-parser.v5` adds explicit EPUB volume ancestry from TOC hierarchy or heading depth.
Stable href/anchor scope identities are separate from display names; repeated names and
chapter numbers do not merge volumes. Scopes persist across verified spine continuation
until an explicit hierarchy boundary. Missing hierarchy requires review. Unit/fragment
mappings carry volume scope and original chapter numbers separately from reading ordinal.
Older parser versions retain their frozen semantics. v5 reprocessing appends to the same
Edition/acquisition; prior number/title conflicts close only when identical source units
and content are distinguished by verified volume scopes. Other issues remain carried.

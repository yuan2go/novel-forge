# 11. 写作生产线 Writing Pipeline

## 1. 模块目标

写作生产线负责将单本小说项目从大纲推进到细纲、正文、审稿、修订和 final。

核心目标：

```text
保证每章有吸引力；
保证每章不违背项目宪法；
保证 DeepSeek 的产能与 ChatGPT/Codex 的质量判断结合；
保证 Claude Code 维护项目上下文和长期一致性。
```

## 2. 生产原则

```text
先细纲，后正文。
先冲突，后设定。
先读者奖励，后多学科解释。
先项目宪法，后模型生成。
```

## 3. 章节最小商业单元

每一章必须具备：

```text
冲突
推进
奖励
代价
钩子
```

缺一项，退回细纲。

## 4. 章节生成总流程

```text
Claude Code 读取：
  project_constitution.md
  current_context.md
  chapter_plan.md
  character_state.md
  unresolved_foreshadowing.md

  ↓

检查章节最小商业单元

  ↓

DeepSeek 生成 v0

  ↓

ChatGPT/Codex 审稿：
  商业审稿
  逻辑审稿
  心理审稿
  世界观审稿
  原创风险审稿

  ↓

Claude Code 整合修改意见

  ↓

生成 v1 / v2

  ↓

人类主编确认 final

  ↓

更新 memory
```

## 5. 正文版本定义

| 版本 | 作用 | 负责人 |
|---|---|---|
| v0 | 初稿 | DeepSeek |
| v1 | 结构与节奏修订 | Claude Code + DeepSeek |
| v2 | 高质量审稿后修订 | ChatGPT/Codex + Claude Code |
| final | 发布稿 | 人类主编确认 |

```markdown

3. 是否缺少代价？
```

## 7. 正文写作规则

```text
1. 先动作，后解释；
2. 先冲突，后设定；
3. 每 500-800 字有一次信息增量或情绪变化；
4. 不让角色替作者解释世界观；
5. 爽点必须通过行动兑现；
6. 主角胜利必须有代价；
7. 结尾必须留追读钩子；
8. 不写 AI 腔总结式结尾；
9. 不能让多学科知识压过情绪；
10. 哲学只能通过选择、代价、冲突体现。
```

## 8. 前 3 章生产标准

前 3 章决定读者是否留下。

### 第 1 章

必须完成：

```text
抛出异常事件；
呈现主角压迫；
建立主角欲望；
留下强钩子。
```

### 第 2 章

必须完成：

```text
主角被迫入局；
敌人或制度压力加码；
主角第一次主动行动；
扩大谜题或冲突。
```

### 第 3 章

必须完成：

```text
第一次小反转或小胜利；
让读者确认主角值得跟；
引出更大压力；
建立前 10 章追读期待。
```

## 9. 前 10 章生产标准

前 10 章必须兑现第一次读者奖励。

可选奖励：

```text
一次反杀；
一次打脸；
一次身份反转；
一次关键揭秘；
一次资源获得；
一次关系推进；
一次能力升级；
一次情绪释放。
```

## 10. 连载节奏计划

```markdown
# 连载节奏计划

## 前 3 章目标

## 前 10 章目标

## 前 30 章目标

## 每章最低要求

1. 一个明确冲突；
2. 一个信息增量；
3. 一个情绪变化；
4. 一个读者奖励；
5. 一个结尾钩子。
```

## 11. 生产验收标准

每章生成后必须检查：

1. 是否有冲突；
2. 是否有推进；
3. 是否有奖励；
4. 是否有代价；
5. 是否有钩子；
6. 是否违背项目宪法；
7. 是否角色降智；
8. 是否世界规则失效；
9. 是否有原创风险；
10. 是否有明显 AI 腔。

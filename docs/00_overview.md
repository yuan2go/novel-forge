# 00. NovelForge 项目总览

## 1. 项目定位

NovelForge 是一个小说宇宙工厂，不是单纯的 AI 写作工具。

它的目标是把小说创作拆成可管理、可审稿、可复盘、可迭代的工业流程：

```text
通用知识沉淀
  ↓
项目孵化
  ↓
项目宪法
  ↓
单本小说执行
  ↓
连载反馈
  ↓
全局知识回流
```

## 2. 解决的问题

传统 AI 小说生成容易出现：

1. 第一章没有钩子；
2. 主角欲望不清；
3. 设定堆砌但故事无力；
4. 反派降智；
5. 世界观前后矛盾；
6. 资源、权力、社会运行不可信；
7. 评论反馈导致大纲失控；
8. 多本小说风格与结构同质化；
9. 经验无法复用；
10. AI 生成内容缺少主编判断。

NovelForge 的设计目标是用流程和边界解决这些问题。

## 3. 核心生产链路

```text
用户创意
  ↓
总编 Agent 访谈
  ↓
Reader Attraction Gate
  ↓
Project Differentiation Gate
  ↓
Knowledge Compiler
  ↓
Project Constitution
  ↓
Novel Workspace
  ↓
Claude Code 接管
  ↓
DeepSeek 生产 v0
  ↓
ChatGPT/Codex 审稿
  ↓
Claude Code 修订 v1/v2
  ↓
人工主编确认 final
  ↓
评论反馈受控进入后续创作
```

## 4. 四个核心概念

### 4.1 读者吸引力 Gate

用于判断一本小说是否值得写。它优先于世界观、多学科知识和哲学命题。

核心问题：

```text
读者为什么点进来？
第一章为什么看完？
前三章为什么追读？
前十章是否兑现奖励？
```

### 4.2 项目差异化 Gate

用于防止多本小说因为共用知识库而同质化。

检查：题材、主角欲望、哲学命题、世界模板、爽点来源、反派结构、语言风格等是否与已有项目重复。

### 4.3 知识编译器

通用知识不能直接写小说。知识编译器负责把网文拆解、多学科知识、哲学命题、世界模板编译成某一本小说专属的项目知识包。

### 4.4 项目宪法

项目宪法是单本小说的最高规则，约束 Claude Code、DeepSeek、ChatGPT/Codex 和评论反馈。

它定义：目标读者、核心爽点、哲学方向、世界宪法、主角欲望、反馈红线、原创风险边界。

## 5. 模型分工

| 模型 / 工具 | 定位 | 主要任务 |
|---|---|---|
| Claude Code | 单本小说项目总编 | 管理文件、执行任务卡、维护 memory、调度模型 |
| ChatGPT/Codex | 高质量判断与审稿 | 立项、知识编译、哲学方向、审稿、代码辅助 |
| DeepSeek | 生产与批处理 | 网文拆解、知识卡初稿、正文 v0、评论分类 |
| 人类主编 | 最终判断 | 是否立项、是否采纳反馈、是否发布 |

## 6. 系统最高优先级

```text
P0：原创风险与安全边界
P1：读者吸引力
P2：项目差异化
P3：多学科可信度
P4：哲学方向
P5：世界观完整性
P6：生产效率
P7：自动化程度
```

## 7. 第一阶段目标

第一阶段不追求完整 Web 平台，而是先跑通文件项目制：

```text
1. 建立小型全局知识库；
2. 建立世界模板库；
3. 建立 Reader Attraction Gate；
4. 建立 Project Differentiation Gate；
5. 建立 Knowledge Compiler 模板；
6. 生成 project_constitution.md；
7. 初始化单本小说 workspace；
8. Claude Code 接管；
9. 生成前 10 章细纲；
10. 生成前 3 章 v0/v1/v2；
11. 完成审稿和反馈模拟。
```

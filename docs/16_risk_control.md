# 16. 风险控制 Risk Control

## 1. 模块目标

风险控制模块用于防止小说生产过程中的四类核心风险：

```text
原创风险
同质化风险
剧情失控风险
设定过重风险
```

## 2. 原创风险

### 2.1 风险来源

```text
直接拆解单一小说后仿写；
复用具体桥段；
复用具体台词；
复用具体人物关系；
复用独特反转；
复用独特世界观设定；
章节顺序过度接近原作品。
```

### 2.2 控制方法

```text
1. 原文不进入生成 prompt；
2. 只保存抽象知识卡；
3. 禁止复用具体桥段；
4. 每张知识卡标记 forbidden_usage；
5. 每章进行原创风险审稿；
6. 禁止只拆一本小说后仿写；
7. 多来源混合机制后再生成原创结构。
```

### 2.3 原创风险审稿问题

```text
是否复用了已有作品具体场景？
是否复用了已有作品人物身份？
是否复用了已有作品台词？
是否复用了独特反转？
是否只是换名字和换背景？
是否混合了多个来源的抽象机制？
```

## 3. 同质化风险

### 3.1 风险来源

多本小说共用：

```text
同一套知识卡；
同一类世界模板；
同一类主角；
同一类哲学命题；
同一类爽点结构；
同一类反派。
```

### 3.2 控制方法

```text
1. Project Differentiation Gate；
2. 项目矩阵；
3. 哲学命题差异；
4. 主角欲望差异；
5. 世界区域差异；
6. 风格差异；
7. 反派结构差异；
8. 前三章钩子差异。
```

## 4. 剧情失控风险

### 4.1 风险来源

```text
评论反馈过度影响；
Claude Code 无任务卡自由修改；
大纲不断加设定；
主角欲望漂移；
反派逻辑变化；
世界规则随剧情变化；
final 文件被自动覆盖。
```

### 4.2 控制方法

```text
1. 项目宪法；
2. 世界宪法；
3. 任务卡制度；
4. Git 快照；
5. final 文件保护；
6. 反馈红线；
7. 主编确认机制；
8. decision_log。
```

## 5. 设定过重风险

### 5.1 风险来源

```text
多学科知识过度进入正文；
世界观先行，主角滞后；
哲学变成说教；
解释多于行动；
前十章没有奖励兑现。
```

### 5.2 控制方法

```text
1. Reader Attraction Gate 前置；
2. 每章最小商业单元；
3. 正文先冲突后设定；
4. 多学科知识只服务可信度；
5. 哲学通过选择和代价体现；
6. 禁止大段设定说明。
```

## 6. 反馈失控风险

### 6.1 风险来源

```text
读者喜欢配角，于是配角抢主线；
读者要求爽，于是破坏代价机制；
读者反感反派，于是削弱压迫；
单日评论导致大纲大改；
评论要求违背项目宪法。
```

### 6.2 控制方法

```text
1. S/A/B/C 分级；
2. 评论默认只影响后续 3-10 章；
3. 不改项目宪法；
4. 不改哲学终局；
5. 不改世界第一规则；
6. 不让配角抢走主角成长线；
7. 重大调整必须主编确认。
```

## 7. 风险检查表

| 风险 | 检查问题 | 处理 |
|---|---|---|
| 原创风险 | 是否接近具体作品桥段 | 退回重构 |
| 同质化风险 | 是否与已有项目过像 | 调整至少三项 |
| 剧情失控 | 是否违背项目宪法 | 停止任务 |
| 设定过重 | 是否解释多于行动 | 退回细纲 |
| 反馈失控 | 是否让评论改核心规则 | 不采纳 |
| 人物崩坏 | 是否违背人物心理 | 退回重写 |
| 世界崩坏 | 是否违背世界第一规则 | 退回重构 |

## 8. 验收标准

风险控制系统必须保证：

1. 所有生成任务受项目宪法约束；
2. 所有章节有原创风险检查；
3. 所有反馈有采纳记录；
4. 所有重大修改有决策日志；
5. final 文件不会被自动覆盖；
6. 通用知识不会直接进入正文；
7. 多项目之间有差异化检查。

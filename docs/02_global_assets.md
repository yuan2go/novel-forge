# 02. 全局资产层 Global Assets

## 1. 模块目标

全局资产层是 NovelForge 的知识中台，负责沉淀可跨项目复用的知识资产。

它不直接生成正文，而是为项目孵化和知识编译提供材料。

## 2. 核心原则

```text
通用知识只能提供结构、规律、机制和检查项。
通用知识不能直接进入正文。
通用知识必须通过 Knowledge Compiler 编译成项目知识包。
```

## 4. 网文商业结构库

### 4.1 目标

解决小说是否好看、是否有追读、是否能持续制造情绪奖励。

### 4.2 资产类型

| 类型 | 用途 |
|---|---|
| trope_cards | 套路机制卡，保存抽象结构 |
| hook_cards | 章节钩子卡 |
| conflict_cards | 冲突模型卡 |
| character_mechanism_cards | 人设机制卡 |
| emotion_curve_cards | 情绪曲线卡 |
| commercial_logic_cards | 商业化逻辑卡 |

### 4.3 可学习内容

允许沉淀：

```text
结构
节奏
冲突模式
钩子类型
爽点类型
读者奖励方式
情绪曲线
角色功能
商业化逻辑
```

禁止沉淀和复用：

```text
具体人物
具体台词
具体案件
具体桥段
具体反转
具体世界观独特设定
章节顺序的照搬
```

## 5. 多学科可信度知识库

### 5.1 目标

多学科知识解决可信度，不负责直接制造爽点。

| 学科 | 解决的问题 |
|---|---|
| 心理学 | 人物行为为何可信 |
| 逻辑学 | 剧情因果为何成立 |
| 经济学 | 资源、价格、垄断、组织成本为何合理 |
| 政治学 | 权力、合法性、派系斗争为何成立 |
| 社会学 | 阶层、群体、舆论为何真实 |
| 历史学 | 世界为何发展成现在这样 |
| 法学 | 规则、契约、惩罚、审判如何运行 |
| 军事学 | 暴力、军队、补给、战争为何可信 |
| 地理学 | 城市、资源、交通、文明分布为何合理 |
| 生态学 | 环境、灾害、承载力如何影响世界 |
| 组织管理学 | 宗门、公司、帮派、军队如何运作 |
| 传播学 | 谣言、名声、宣传、信息战如何发生 |
| 语言学 | 阶层语言、职业黑话、命名规则如何建立 |
| 哲学 | 整本书讨论什么价值冲突 |

## 6. 哲学命题库

哲学命题库用于提供整本书的方向轴。

哲学不是说教，而是：

```text
主角信念
反派合理性
世界底层冲突
关键选择
代价
结局答案
```

### 6.1 哲学轴示例

```markdown
# 哲学轴：自由 vs 秩序

## 核心问题

如果自由会导致混乱，人是否仍然应该追求自由？

## 主角常见立场

主角追求自由，反抗被安排的人生。

## 反派常见立场

反派认为大多数人无法承担自由，秩序虽然压迫，但能避免崩溃。

## 剧情压力转译

不要让角色直接讨论自由。
应设计为：

- 主角公开真相可以救一个人，但会让城市系统崩溃；
- 主角破坏规则可以反杀敌人，但会连累无辜者；
- 主角获得自由，但其他人失去保护。

## 禁止写法

- 禁止角色长篇讲道理；
- 禁止章节末尾强行升华；
- 禁止让反派只是错误口号。
```

## 7. 读者反馈规律库

当多个项目反复出现相似读者反馈，可以升级为全局规律。

示例：

```text
多个项目读者都抱怨主角连续受压太久。
```

升级为规则：

```text
主角连续受压不得超过 3 章，除非第 4 章给予信息胜利、行动胜利或情绪补偿。
```

## 8. 审稿规则库

审稿规则库保存全局审稿标准：

1. 商业审稿；
2. 逻辑审稿；
3. 心理审稿；
4. 世界观审稿；
5. 原创风险审稿；
6. 反馈控制审稿。

## 9. 维护规则

每张知识卡必须包含：

```text
来源
抽象程度
可用范围
禁用范围
适用题材
审稿检查项
原创风险等级
```

禁止把原文、桥段、台词、独特反转直接保存为可生成素材。

# 07. Knowledge Compiler 知识编译器

## 1. 模块目标

Knowledge Compiler 是 NovelForge 的核心转换层。

它负责把全局资产中的通用知识编译成某一本小说专属的项目知识包。

核心原则：

```text
通用知识不能直接进入正文。
通用知识必须先被筛选、冲突消解、项目化改写，再进入单本小说项目。
```

## 2. 为什么需要知识编译器

如果直接把全局知识交给 Claude Code 或正文模型，会导致：

1. 知识过载；
2. 项目方向混乱；
3. 多本小说同质化；
4. 世界观设定过重；
5. 哲学变成说教；
6. 多学科知识互相冲突；
7. 正文变成论文；
8. 模型上下文成本过高。

知识编译器解决的是：

```text
哪些知识适合这本书？
哪些知识必须排除？
哪些知识要改写成本书专属规则？
哪些知识只作为审稿检查项？
```

## 3. 输入

```text
reader_attraction_gate.md
project_differentiation_gate.md
项目候选方案
目标读者
世界模板 / 世界实例
哲学方向
网文商业结构卡
多学科可信度卡
审稿规则卡
禁用素材
```

## 4. 输出

```text
project_knowledge_pack/
├── commercial_pack.md
├── philosophy_pack.md
├── credibility_pack.md
├── world_pack.md
├── character_pack.md
├── plot_logic_pack.md
├── style_pack.md
├── feedback_control_pack.md
└── originality_risk_pack.md
```

## 5. 编译流程

```text
1. 读取 Reader Attraction Gate；
2. 确认本书吸引力来源；
3. 读取 Project Differentiation Gate；
4. 排除与已有项目过度相似的知识；
5. 检索网文商业结构卡；
6. 检索多学科可信度卡；
7. 检索哲学轴；
8. 检索世界模板；
9. 选择适用知识；
10. 删除不相关知识；
11. 解决知识冲突；
12. 改写成本书专属规则；
13. 生成 project_knowledge_pack；
14. 为项目宪法提供输入。
```

## 14. originality_risk_pack.md

控制原创风险。

必须回答：

```text
参考了哪些通用结构？
哪些内容禁止复用？
哪些桥段有相似风险？
哪些世界设定需要重构？
生成正文时必须避开的表达是什么？
```

## 15. 编译验收标准

一个 project_knowledge_pack 必须满足：

1. 能支撑本书读者吸引力；
2. 不复制已有作品具体内容；
3. 不与已有项目高度同质化；
4. 每个知识包都有明确边界；
5. 每个知识包都能转化为项目宪法；
6. 不包含无关知识；
7. 不把多学科知识写成正文解释；
8. 能直接交给 Claude Code 接管。

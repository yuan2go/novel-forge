# Acceptance Criteria

## 1. 模块目标

定义 `novel-forge` 中 AI 代理执行任务后的统一验收标准，避免任务完成口径依赖口头判断。

## 2. 输入

- 任务卡
- 变更文件
- diff 摘要
- `make check` 输出
- `make test` 输出
- 审稿报告或质量检查报告

## 3. 输出

- `accepted`：可进入下一阶段。
- `needs_revision`：需要返工。
- `blocked`：需要主编或项目负责人决策。
- 缺陷清单和风险清单。

## 4. 文件路径

```text
docs/ai-workflow/acceptance-criteria.md
```

## 5. 执行流程

1. 检查任务卡是否存在且边界明确。
2. 检查实际变更是否超出授权范围。
3. 检查是否触碰禁止文件或禁止行为。
4. 检查新增文档是否包含必需章节。
5. 检查脚本是否只使用 Python 标准库。
6. 检查 `make check` 和 `make test` 是否按任务需要运行。
7. 检查输出是否包含变更文件列表、diff 摘要和风险说明。
8. 给出 `accepted`、`needs_revision` 或 `blocked` 结论。

## 6. 验收标准

工程任务必须满足：

- 变更范围与任务卡一致。
- 未删除已有文件。
- 未安装依赖。
- 未引入数据库、外部服务或复杂 Agent 平台。
- 未读取或写入真实密钥。
- 必要检查已运行并通过，或明确说明无法运行原因。

文档任务必须满足：

- 包含模块目标、输入、输出、文件路径、执行流程、验收标准、风险与边界。
- 不与 `AGENTS.md`、`CLAUDE.md` 和项目 V1 路线冲突。
- 不扩大 AI Agent 权限。

写作任务必须满足：

- 符合项目宪法。
- 保留读者吸引力和章节商业单元。
- 不突破原创风险边界。
- DeepSeek 产物只作为 v0 或候选稿。
- 终稿必须经过审稿流程。

## 7. 风险与边界

- 验收标准不能替代主编判断。
- 高风险原创问题、项目宪法冲突和重大主线转向必须升级为 `blocked`。
- 测试未运行时不得声称通过。
- 工程自动化不能覆盖写作质量判断。

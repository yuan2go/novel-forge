# 12. 审稿系统 Review System

## 1. 模块目标

审稿系统负责检查小说是否具备商业吸引力、逻辑可信度、人物合理性、世界一致性和原创安全性。

审稿不是为了把小说写成论文，而是为了让小说：

```text
更好看；
更可信；
不崩；
不侵权；
不失控；
能持续连载。
```

## 2. 审稿优先级

审稿不能所有维度平权。商业网文必须优先保留追读和情绪。

```text
P0：原创风险、设定崩坏、严重逻辑断裂
P1：读者吸引力、钩子、冲突、爽点
P2：人物心理合理性
P3：世界观、经济、政治、社会可信度
P4：哲学表达、语言风格
```

原则：

```text
多学科合理性必须服务追读。
不能为了合理，把小说写成论文。
不能为了哲学，把章节写成说教。
```

## 3. 审稿类型

| 审稿类型 | 检查内容 | 推荐模型 |
|---|---|---|
| 商业审稿 | 开头钩子、冲突、读者奖励、结尾追读 | ChatGPT/Codex |
| 逻辑审稿 | 因果链、线索、反转、代价 | ChatGPT/Codex |
| 心理审稿 | 人物动机、压力反应、人设一致 | ChatGPT/Codex |
| 世界观审稿 | 规则是否自洽 | ChatGPT/Codex |
| 经济审稿 | 资源、价格、垄断、组织成本 | ChatGPT/Codex |
| 原创风险审稿 | 是否过度接近已有作品 | ChatGPT/Codex |
| 语言审稿 | AI 腔、对白差异、节奏 | DeepSeek 初审 + ChatGPT/Codex 复审 |

## 4. 章节评分表

| 维度 | 分值 |
|---|---:|
| 开头钩子 | 10 |
| 本章冲突 | 10 |
| 读者奖励 | 10 |
| 结尾追读 | 10 |
| 主角推动力 | 10 |
| 人物心理 | 10 |
| 因果逻辑 | 10 |
| 世界观一致性 | 10 |
| 语言风格 | 10 |
| 原创风险 | 10 |

评分标准：

```text
90-100：可进入 final
80-89：小修后发布
70-79：退回 v1 重修
70 以下：退回细纲
```

## 5. 商业审稿

检查问题：

```text
1. 开头是否有钩子？
2. 本章冲突是否明确？
3. 读者本章获得什么奖励？
4. 主角是否主动推进？
5. 结尾是否有追读？
6. 是否连续解释过多？
7. 是否连续压主角过久？
8. 是否有情绪释放？
```

输出模板：

```markdown
# Commercial Review

## 章节

## 总分

## 开头钩子评分

## 冲突评分

## 读者奖励评分

## 结尾追读评分

## 主要问题

## 修改建议

## 是否退回细纲
```

## 6. 逻辑审稿

检查：

```text
重大结果是否具备动机、条件、行动、阻力、代价、后果；
线索是否提前铺垫；
反转是否公平；
主角推理是否有证据；
反派失败是否有必要原因。
```

## 7. 心理审稿

检查：

```text
主角行为是否符合欲望与恐惧；
角色压力反应是否合理；
创伤是否影响选择；
反派是否有心理收益；
配角是否只是剧情工具；
人物是否突然降智或突变。
```

## 8. 世界观审稿

检查：

```text
是否违背世界第一规则；
力量是否无代价膨胀；
资源是否凭空出现；
权力是否没有成本；
法律是否只在剧情需要时生效；
社会反应是否真实。
```

## 9. 原创风险审稿

检查：

```text
是否复用了已有作品具体桥段；
是否复用了具体台词；
是否复用了独特反转；
是否只是在换名仿写；
是否过度接近单一参考作品；
是否混合了多来源抽象结构。
```

## 10. 语言审稿

检查：

```text
是否有 AI 腔总结；
是否大段空泛心理描写；
角色说话是否同质化；
战斗/推理/情绪场景节奏是否匹配；
是否过度解释设定。
```

## 12. 审稿验收标准

一次有效审稿必须：

1. 明确评分；
2. 明确是否退回；
3. 区分问题优先级；
4. 给出可执行修改建议；
5. 不用多学科合理性压制商业追读；
6. 不建议破坏项目宪法；
7. 不随意修改 final；
8. 记录到 reviews/ 和 decision_log。

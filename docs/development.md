# Development rules

## Repository map

- `src/novel_forge/api/` — FastAPI composition, HTTP models and thin routers.
- `src/novel_forge/cli/` — executable CLI entry points.
- `src/novel_forge/infrastructure/` — environment and process-shared composition.
- `src/novel_forge/modules/` — domain and application Authorities.
- `src/novel_forge/storage/` — PostgreSQL UoW, repositories, migrations and object store.
- `src/novel_forge/workers/` — bounded worker entry points.
- `src/novel_forge/tools/` and `scripts/` — static checks and explicit verification.
- `tests/` — unit, architecture, acceptance and PostgreSQL integration evidence.
- `web/admin/` — independent Next.js administrative client.
- `architecture/manifests/` — machine-checked runtime, migration, test-Reality and
  instruction-surface contracts.
- `skills/` — repository Skill source; runtime copies are generated by the sync command.

## Change boundary

Start from executable code, schema, migration, composition and tests. A document cannot
authorize a runtime change. Keep fixes inside the owning module and avoid adding a second
state owner, execution path, Provider path or persistence model.

For each behavior change, identify the entry point, application, domain owner, mutation
transaction, persistence, migration impact, retry/recovery behavior and test evidence.
This requirement also applies when a new class appears to be locally isolated.

## Documentation

Only the files listed in `docs/README.md` are canonical. They contain current behavior
and executable procedures, not delivery history, session logs, completion narratives or
future architecture.

Update `architecture/reality-evidence.json` when a capability owner, entry, application,
domain symbol, operation, state owner, mutation boundary, persistence/effect boundary,
dependency, qualification test or status changes. Its projection source is bound to the
implementation-tree identity, so any covered code, test, manifest or instruction change
must make an unrefreshed projection fail. The inventory points to evidence; it does not
duplicate generated implementation detail or become a design Authority.

Semantic constraints use only `CURRENT_PROVEN_INVARIANT`, `CURRENT_RUNTIME_FACT`,
`CONFIGURABLE_POLICY`, `HISTORICAL_COMPATIBILITY`, or
`UNRESOLVED_DESIGN_CONSTRAINT`. Only the first may be documented as an architecture
invariant; the last always requires an explicit design review marker.

Repository-local design candidates remain outside canonical documentation and runtime
Authority. An active proposal, when present, visibly declares `PROPOSAL` and
`NOT_RUNTIME_AUTHORITY` and carries one inline lifecycle record: status, exact reviewed
Reality baseline, scope, implemented/superseding references and unresolved decisions or
work. The checker rejects stale scope/review windows, contradictory implementation
claims, missing decisions beyond the closure window and retained terminal proposals.
`NOT_IMPLEMENTED` is forbidden once implementation evidence exists. Project resolved,
rejected or superseded decisions into current Reality where applicable, then delete the
terminal file; Git preserves history. This is not an alternate runtime evidence registry.

## Comments and docstrings

Comments explain a correctness reason that code cannot state directly: transaction or
concurrency invariants, lease/fence/idempotency rules, protocol compatibility, security,
non-obvious algorithms, third-party constraints, or required tooling annotations.

Do not narrate module responsibility, repeat a call chain, record delivery history,
describe a former architecture, predict a future architecture, or use TODO-style text as
design storage. Production docstrings are allowed only when prefixed with
`INVARIANT:`, `CONSTRAINT:`, `SECURITY:`, or `COMPATIBILITY:`.

`python -m novel_forge.tools.documentation_reality --repo-root .` enforces the canonical
document allowlist, evidence references, repository paths, historical/speculative comment
tokens and docstring classification. Every ordinary non-migration production comment is
classified as `WHY`, `INVARIANT`, `CONSTRAINT`, `WORKAROUND`, `SECURITY`, or
`COMPATIBILITY`; published migration bodies remain immutable compatibility evidence. A
merge-base ratchet rejects increases in source comments, docstrings or Web comments, so a
change cannot raise a repository-local numeric budget to admit itself.

## Agent instructions and tests

`architecture/manifests/ai-instruction-manifest.yaml` inventories Coding Agent policy,
root Skills, model instructions, prompt bindings and code-embedded instructions. The
instruction check rejects hidden sources and generated Claude runtime-Skill drift. Declared
instruction files are part of implementation-tree identity, including files outside the
normal backend identity scope.

`architecture/manifests/test-manifest.yaml` classifies every collected test by current
domain/runtime/Authority proof, migration compatibility, retirement guard, fixture
protocol or qualification infrastructure. The Test Reality check derives production
targets where possible and enforces semantic-slice proof ceilings; migration, retirement
and fixture evidence cannot alone qualify current business capability.

Mock-heavy domain tests are demoted to fixture support, including imported scripted or
mock helpers. Current semantic slices also require direct contract/runtime tests of their
declared concrete production targets; a manifest label or unrelated direct test cannot
promote fixture evidence. Every retained test keeps an owner, classification, target and
proof ceiling. `HISTORICAL_REDUNDANT` is forbidden, not an archival class to retain.

## Every-change governance

`make pr-governance PR_BASE_SHA=<exact-base-sha>` compares clean committed implementation
identities and delegates to the repository's existing checks. Unchanged implementation
still runs governance, with qualification `NOT_REQUIRED / SAME_IMPLEMENTATION`.
Implementation changes run changed non-PostgreSQL tests and then the complete canonical
exact-SHA P0, including PostgreSQL, migration and recovery tests. A failed child gate
prevents PASS; the final source identity must remain unchanged.

The checked workflow calls this same entry point. Provider, prompt, Skill, Context or
execution changes invalidate previously retained real-Provider evidence through the
implementation identity. The PR gate never itself confers Provider qualification.
Repository-local enforcement does not establish remote Actions or branch protection;
operators must verify those controls separately before claiming merge enforcement.

## Skills

Edit root `skills/` only. Synchronize ignored runtime copies with:

```bash
make sync-skills
make check-skills
make instruction-reality-check
make test-reality-check
```

Skills cannot bypass schema validation, Authority ownership, source isolation, Provider
controls, permissions, trace/cost evidence or quality gates.

The 38 vendored Skills from [mattpocock/skills](https://github.com/mattpocock/skills/tree/6fd947921b935b7e1e69293a200400f0fdd5c15f)
are pinned to commit `6fd947921b935b7e1e69293a200400f0fdd5c15f` (upstream package
version `1.3.1`). Each directory retains the upstream MIT `LICENSE`, references,
agent metadata and templates; `skills/pr/CREDITS.md` retains its additional attribution.
The instruction manifest classifies these as coding-agent tools. Existing Novel OS
Skills own production workflows; these additions do not alter Capability Pack bindings.
The seven upstream `in-progress` Skills remain experimental. Files are flattened into
the root Skills directory; the corresponding Codex discovery directory links to that source,
and `make sync-skills` generates the Claude Code copies. Upstream invocation flags
remain intact; installing a Skill does not run it or configure its external services.

Generic decision-reference examples in pinned coding tools are advisory text. The
historical-reality policy binds the two upstream files by full content digest and
coding-only instruction classification, including identical generated copies. Changed
bytes or a runtime consumer fail the exception; retired ontology and machine-field
checks still apply. These examples create no additional canonical documents.

Installation requires Python and GitHub download access, with no npm packages needed.
On invocation, tracker workflows can use authenticated `gh` or `glab`, research can
use network retrieval, and `claude-handoff` can launch Claude CLI sessions. Package
setup Skills can install Husky, lint-staged, Prettier, dependency-cruiser or
the @total-typescript/shoehorn package through the project's package manager. These are optional
workflow dependencies, not installed dependencies of Novel Forge. Provider calls,
external writes and credentials remain subject to the user's task and repository rules.

Bundled executable material is limited to `skills/diagnosing-bugs/scripts/hitl-loop.template.sh`
(Bash prompts), `skills/git-guardrails-claude-code/scripts/block-dangerous-git.sh` (Bash and
`jq`, rejects matching Git commands), `skills/wizard/template.sh` (Bash, browser opening,
`.env` writes and optional GitHub secret/variable writes via `gh`), and
`skills/setup-ts-deep-modules/dependency-cruiser.config.cjs` (Node configuration). Installation
does not execute these files or install hooks. Verify intake with frontmatter and
upstream byte comparisons, `make sync-skills-dry-run`, `make sync-skills`,
`make check-skills`, `make instruction-reality-check` and `git diff --check`.

## Adding or changing a capability

1. Add or change executable behavior in the owning module.
2. Add a migration only when persistence changes; keep the linear registry and manifest
   exact.
3. Wire the real API, CLI, worker or composition entry.
4. Add focused unit and PostgreSQL tests, including failure and replay behavior.
5. Update the appropriate architecture manifest.
6. Update the reality inventory and only the canonical prose affected by the code.
7. Run the validation matrix in `docs/runtime-operations.md`.

Never edit business code merely to make prose appear correct. A discovered architecture
gap is a separate scoped change with its own executable acceptance evidence.

# Quality Review

## 适用场景

- 审查题材、世界观、人物、大纲、细纲、正文或反馈采纳方案。
- 正文草稿进入 final 前。
- 需要判断是否退回细纲、重写、局部修订或主编决策。

## 输入要求

- 审稿对象文件路径和版本。
- 项目宪法、细纲或大纲、人物状态、世界规则。
- 原创风险边界、读者吸引力目标和当前任务验收标准。

## 操作流程

1. 标记审稿对象、版本、输入依据和输出位置。
2. 先查 P0：原创风险、设定崩坏、严重逻辑断裂。
3. 再查 P1：读者吸引力、冲突、爽点、结尾追读。
4. 检查人物动机链、因果链、世界规则、伏笔设置与回收。
5. 检查节奏、叙述密度、AI 腔、对白差异和商业化弱点。
6. 给出评分、优先级、是否退回和可执行修改建议。
7. 明确哪些内容不建议改，避免破坏项目宪法或已有优势。

## 输出格式

```markdown
# Quality Review

## 审稿对象

## 版本

## 总分

## 结论

通过 / 小修 / 重修 / 退回细纲 / 暂停

## P0 问题

## P1 问题

## P2 问题

## P3 问题

## P4 问题

## 可执行修改建议

## 不建议修改内容

## 是否需要主编决策
```

## 质量标准

- 审稿必须区分问题优先级。
- 修改建议必须能直接转成任务卡或修订指令。
- 不能只给泛泛评价，必须指出具体问题位置或问题类型。
- 商业追读和原创边界优先于炫技式设定补完。

## 禁止事项

- 禁止直接覆盖正文终稿。
- 禁止降低原创风险标准。
- 禁止用多学科合理性压制章节爽点。
- 禁止建议突破项目宪法或世界第一规则。

## 与其他模块的关系

- 上游：全部创作产物、`anti-copy-abstraction`、项目宪法、审稿系统。
- 下游：修订任务、决策日志、反馈控制、final 审批。
- Agent：审稿 Agent、质量检查 Agent、主编 Agent 使用。

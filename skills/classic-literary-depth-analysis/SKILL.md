# Classic Literary Depth Analysis

## Novel OS Runtime Contract

- 生产输出必须落入 schema-backed Authority asset，并保留 Source/Evidence lineage。
- 经典地位不等于版权许可；public fame、public GitHub 或历史影响力均不能绕过 rights/copyright governance。
- raw source、原句、标志性场景和可识别角色组合不得进入生成 Context；只有经 MKAOS 批准的 KnowledgeCard 可进入 KnowledgePack。

## Source Intelligence Observation Contract

当 stage 为 `source.deconstruction.observe`，或输入包含冻结的 AnalyzerContract / EvidenceSpan 时：

1. 只执行 AnalyzerContract 指定的 dimension 和 scope。不得把一个窗口扩写成整书文学评论。
2. 只使用 supplied Source evidence 或 lower-scale Observations；不得自行读取文件、检索网络或补充未经治理的外部知识。
3. 每条 finding 必须引用 supplied `evidence_span_ids`，聚合模式则引用 supplied lower Observation AssetVersion。
4. 输出严格匹配 Source Observation schema：`findings`、`confidence`、`knowledge_status=NOT_ABSTRACTED`。不得输出 `classic_literary_analysis_report`、KnowledgeCard、Markdown 报告或文件写入指令。
5. 只提炼结构功能，不保存原作人物名、事件顺序、专有象征组合、原句或可识别 set piece。
6. 经典身份本身只允许作为治理 metadata；若 bibliographic evidence 不足，不得由文本风格主观推断“经典”。

## 分析重点

- `structure`: 深层结构、阶段压力、因果推进与命运转折的功能。
- `conflict`: 道德困境、制度压力、社会关系冲突和不可兼得选择。
- `character_mechanism`: 信念、身份、命运压力与人物选择的变化机制。
- `relationship_mechanism`: 家庭、阶层、权力、义务与社会网络的状态变化。
- `emotion_curve`: 悲剧/喜剧压力、延迟、反转、余韵和情绪积累。
- `information_progression`: 叙事视角、知识差、象征信息和意义递进。
- `foreshadowing`: 命运预示、象征回响、结构性伏笔的建立与兑现功能。
- `originality_copyright_risk`: 哪些只可学习抽象功能，哪些具体表达/场景/组合必须隔离。

## Standalone / Operator Handoff

脱离 Canonical Source Import Runtime 时可以生成人工阅读用 `classic_literary_analysis_report`。该报告不是生产 Authority，不能直接作为生成知识；正式使用必须重新进入 Observation → MKAOS → Governance。

## 质量标准

- Theme、symbol、social pressure 和 fate 结论必须有局部证据，不做无证据宏大解读。
- Transferable item 必须是跨作品成立的功能或约束，而不是场景替换模板。
- 受保护元素与不可迁移组合必须明确隔离。

## 禁止事项

- Do not copy protected text or recognizable set pieces.
- Do not preserve source-specific scene order, character constellation, or symbolic sequence.
- Do not write draft prose or imitate a specific author.
- Do not treat canonical status as permission to copy.

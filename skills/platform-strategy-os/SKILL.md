# Platform Strategy OS

## Novel OS Runtime Contract

- 平台策略必须是结构化资产、Observation、Knowledge 或 gate policy，不能只作为提示词语气要求。
- 平台适配不得覆盖 canon facts、人物状态、source isolation、rights 或 originality boundary。
- 真实平台 API 和外部数据导入必须走受治理 ExternalEffect；Source Import 阶段只分析已经纳管的资料。

## Source Intelligence Observation Contract

当 stage 为 `source.deconstruction.observe`，或输入包含 AnalyzerContract / EvidenceSpan 时：

1. 当前输入被视为“平台规则/运营规则来源”，只分析 AnalyzerContract 指定 dimension 和 scope。
2. 只使用 supplied Source evidence 或 lower-scale Observations；不得主动登录平台、访问 Web、读取本地文件或补充未冻结规则。
3. 每条 finding 必须引用 supplied `evidence_span_ids`，聚合模式引用 lower Observation AssetVersion。
4. 输出严格匹配 Source Observation schema：`findings`、`confidence`、`knowledge_status=NOT_ABSTRACTED`。不得输出 Platform Strategy Report、PublishGate、KnowledgeCard 或文件写入指令。
5. 将事实规则、推断策略和商业建议严格分开；只有来源直接支持的规则才能作为 Observation statement。
6. 时效性、地区、平台版本、适用作者类型等边界若无法从证据确定，必须在 finding 中标记不确定性，不得猜测。
7. `originality_copyright_risk` 只分析平台规则文本本身的来源/复用边界，不得把平台规则误当作小说正文素材。

## 分析重点

- `reader_promise`: 平台对读者预期、开篇承诺、内容定位和读者分层的显式约束。
- `serialization`: 更新频率、章节组织、连载节奏、上架/发布周期等来源支持的规则。
- `commercial_logic`: 签约、推荐、订阅、收益或分发机制中可验证的结构性约束；不做无证据收益承诺。
- `originality_copyright_risk`: 内容规范、版权、重复内容、AI/搬运、引用或平台合规边界。

## Production Strategy Mode

当输入不是 Source Import Observation，而是已批准 PlatformProfile、KnowledgePack、Outline、ChapterPlan、ReviewIssue 或反馈数据时，可以：

1. 将平台要求转成节奏规则、开篇门禁、章节门禁、留存风险和发布适配建议；
2. 把风险转为 ReviewIssue、RevisionTask 或 PublishGate warning/blocking；
3. 生成平台相关 next-chapter / next-10-chapter strategy；
4. 通过正式 Feedback Backflow 提出 MKAOS selector/rule 更新候选。

该模式不得读取未经 Source Authority 纳管的参考文本。

## 质量标准

- 平台规则 Observation 必须可追溯到具体 EvidenceSpan。
- 平台策略必须明确区分硬规则、软策略和推断。
- Gate 必须可测试，不能以“更像某平台”这种主观语言替代。
- 任何策略都不能牺牲 canon、一致性、版权边界或 source isolation。

## 禁止事项

- 禁止把平台适配简化成“改文风”。
- 禁止把未经验证的传闻当作平台规则。
- 禁止绕过 Source/MKAOS/Governance 直接把平台资料注入生成上下文。
- 禁止引入与本任务无关的登录、会员、计费或 SaaS 权限系统。
